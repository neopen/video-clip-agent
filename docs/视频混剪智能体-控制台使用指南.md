# PenClip 控制台使用指南

> PenClip 以「人机协同 / 深度参与」为核心，**控制台实时交互是主要使用方式**；REST 异步提交（`/api/v1/tasks`）仅为备用方案。

控制台是一个**交互式 REPL**（Read-Eval-Print Loop）：你输入自然语言指令，系统实时解析意图、评估风险、路由到对应智能体，高风险操作会停下来等你确认。整个过程在同一个会话里持续进行，系统会记住上下文。

---

## 1. 启动控制台

```bash
# 方式一：命令行入口（推荐，需先 pip install -e .）
pip install -e . --no-build-isolation -i https://pypi.tuna.tsinghua.edu.cn/simple
penclip-cli

# 方式二：指定会话 ID（便于恢复/区分不同会话）
penclip-cli --session my-vlog

# 方式三：模块方式（开发环境）
python -m penclip.cli.main
```

> 若使用模块方式且未 `pip install -e`，需先 `export PYTHONPATH=src`（Linux/macOS）或 `set PYTHONPATH=src`（Windows）。

启动后界面：

```
PenClip 交互控制台 — session: sess_1a2b3c4d
先提供本地视频素材路径（V0.1 不下载 URL），再依次 规划 → 分析 → 匹配 → 合成（help 查看完整流程，exit 退出）。
penclip>
```

`penclip>` 是命令提示符，在它后面输入指令回车即可。

---

## 2. 内置命令

| 命令 | 别名 | 说明 |
| :-- | :-- | :-- |
| `help` | `帮助` | 显示帮助信息与 V0.1 出片流程 |
| `capabilities` | `能力` / `能做什么` / `功能` | 列出已注册的智能体能力 |
| `status` | `状态` / `进度` | 查看当前进度（阶段/素材/片段/槽位/撤销深度） |
| `pipeline` | `一键出片` | 依次执行 分析 → 匹配 → 合成，渲染前仍要求确认 |
| `exit` | `quit` / `退出` | 退出控制台 |

> 退出也可直接按 `Ctrl+C`（发送中断）或 `Ctrl+D`（EOF，Linux/macOS）。
> 其余输入都当作自然语言指令交给中枢；「撤销」「重做」也是指令（由 `StateAgent` 处理）。

---

## 3. 三种交互模式

控制台支持三种交互模式，满足从一次性指令到多轮协作的创作过程。

### 3.1 一次性指令

直接输入一句完整指令，系统立即处理：

```
penclip> 能做什么
6 个能力已注册：
  - timeline_planner
  - asset_manager
  - video_analyzer
  - segment_matcher
  - video_composer
  - session_state
```

### 3.2 澄清式对话

当指令**过短（单字）或未命中任何关键词**时，系统会反问，引导你补充细节：

```
penclip> 剪
请详细描述您的需求，例如'把自我介绍放开头，活动放中间，风景放结尾'
penclip> 把自我介绍这段剪到 10 秒
```

### 3.3 渐进式细化

会话状态（`AssemblyState`）按 `session_id` 持续累积：素材、槽位、分析结果、匹配结果都在同一会话里流转，因此指令可以分步下达、也可随时回退。V0.1 的意图识别是关键词表，「这段」「它」这类代词要到 V0.2 的 LLM 解析才可靠。

```
penclip> E:\videos\travel_01.mp4
[OK] 已添加素材: travel_01.mp4

penclip> 做一个旅行 Vlog，风景放开头，美食放中间
确认根据此需求创建新的时间线规划？
确认执行? [y/N] y
[OK] 创建时间线：3 个片段槽位，共 3 个
  Intent: plan_create
  建议：下一步：分析素材 → 匹配片段 → 合成（也可用 pipeline 一次跑完）

penclip> 再追加一段夜景收尾
[OK] 追加时间线：1 个片段槽位，共 4 个
  Intent: plan_append

penclip> 撤销
[OK] 已撤销：再追加一段夜景收尾
  Intent: state_undo
  undone: 再追加一段夜景收尾
  phase: planned
```

> 撤销快照记录的是你的原话，失败的操作不会被写入撤销栈。

## 4. 风险确认（高风险操作必须先确认）

中枢对每个意图做风险评估，**高风险操作不会立即执行**，而是停下来等你确认：

| 风险 | 示例操作 | 策略 |
| :-- | :-- | :-- |
| 低 | 调音量、换转场、预览、查询进度 | 直接执行，可撤销 |
| 中 | 替换素材、裁剪片段、加滤镜 | 执行并高亮，可回退 |
| 高 | 创建/删除规划、最终渲染 | **必须先确认** |

高风险操作会弹出确认提示：

```
penclip> 最终渲染
确认开始最终渲染？渲染开始后中途取消可能导致不完整输出。
确认执行? [y/N]
```

- 输入 `y` / `yes` / `确认` → 执行操作
- 输入 `n` / `no` / `取消` 或直接回车 → 取消操作

```
确认执行? [y/N] n
[OK] 已取消 state_render
  Intent: state_render
```

确认执行：

```
penclip> 合成
确认开始最终渲染？渲染开始后中途取消可能导致不完整输出。
确认执行? [y/N] y
[OK] 已合成 3 个片段 → data\output\composed_output.mp4
  Intent: state_render
  output_path: data\output\composed_output.mp4
  clip_count: 3
  size_bytes: 181234
```

> Composer 在返回成功前会自检：输出文件非空、可解码、音视频时长差在阈值内；任一不满足都会以 `[FAIL]` 报告，不会假装出片成功。

## 5. 会话管理

- **默认自动生成**会话 ID（`sess_` + 8 位十六进制，如 `sess_9f2c1b7e`），同一进程内的对话共享上下文。
- 指定 `--session my-vlog` 可让多次启动复用同一会话标识。
- 上下文（对话历史、待确认操作）保存在内存中，进程退出即清空；持久化将在 V0.2 接入 SQLite。
- V0.1 的意图识别是关键词表，「把第二段换成夜景素材」这类**依赖代词/序数的追问要到 V0.2 才可靠**；当前请按「素材路径 → 规划 → 分析 → 匹配 → 合成」的顺序明确下达指令。

## 7. 与 REST 异步的关系

| 方式 | 定位 | 特点 |
| :-- | :-- | :-- |
| 控制台（REPL） | **主要** | 实时交互、支持确认与澄清、上下文连续 |
| REST 异步（`/api/v1/tasks`） | 备用 | 提交任务取 `task_id`，轮询结果，适合脚本/服务集成 |

两者共用同一个 `CentralHub` 与同一套会话状态（按 `session_id` 归并）。REST 路径下高风险操作同样不会直接执行：任务结果返回 `needs_confirmation: true` 与 `confirmation_message`，需要再调用确认端点才会真正放行——这是「深度参与」约束在两种表面的一致体现。

```bash
# 1) 建会话（也可跳过，提交任务时自带 session_id）
curl -X POST http://localhost:8000/api/v1/sessions \
  -H "Content-Type: application/json" -d '{"session_id": "demo-vlog"}'

# 2) 提交高风险指令
curl -X POST http://localhost:8000/api/v1/tasks \
  -H "Content-Type: application/json" \
  -d '{"user_input": "做个混剪：红色开头，绿色中间，蓝色结尾", "session_id": "demo-vlog"}'

# 3) 轮询结果 —— 此时只会看到 needs_confirmation: true
curl http://localhost:8000/api/v1/tasks/{task_id}/result

# 4) 放行（或放弃）
curl -X POST http://localhost:8000/api/v1/tasks/sessions/demo-vlog/confirm
curl -X POST http://localhost:8000/api/v1/tasks/sessions/demo-vlog/cancel   # 取消，状态保持不变

# 5) 查看会话进度
curl http://localhost:8000/api/v1/sessions/demo-vlog
```

> 素材、时间线、导出、Webhook 四组端点在 V0.1 仍返回 `501`，不要期待它们能替代上面这条任务链路。

## 8. 常见问题

| 问题 | 处理 |
| :-- | :-- |
| 提示 `No capability registered` | 未注册智能体；通过 `penclip-cli` 入口启动会自动注册 6 个核心智能体 |
| 输入被反问「请详细描述」 | 指令过短或未命中关键词，补充更完整的描述即可 |
| 想跳过确认直接执行 | 当前设计不允许高风险操作跳过确认（人机协同约束） |
| 「撤销」列表里有一条没发生的变化 | 不会——执行失败的操作不写入撤销栈，栈里只有真正改变过状态的指令 |
| 退出后能恢复上次对话吗 | V0.1 内存态暂不支持跨进程恢复，V0.2 接入 SQLite 后支持 |
