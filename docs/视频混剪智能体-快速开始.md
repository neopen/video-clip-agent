# PenClip 快速开始

> 用最少步骤让服务跑起来并发起第一次视频混剪请求。全程约 5 分钟。

## 1. 总览

```mermaid
flowchart LR
    A[克隆仓库] --> B[创建虚拟环境]
    B --> C[安装依赖]
    C --> D[配置 AI 提供商]
    D --> E[python main.py 启动]
    E --> F[curl /health 验证]
    F --> G[POST /api/v1/tasks 提交指令]
    G --> H[轮询 result + confirm 过确认门]

    style E fill:#e8f5e9
    style G fill:#e3f2fd
```

> 交互式出片请用控制台 `penclip-cli`（见《视频混剪智能体-控制台使用指南.md》）；REST 是脚本/服务集成的备用通道。

## 2. 环境要求

| 依赖 | 版本/说明 | 必需 |
| :-- | :-- | :-- |
| Python | 3.9+ | ✅ |
| FFmpeg | 配置到 PATH，或由项目自动检测/内置 | ✅ |
| 磁盘 | 足够空间存视频与输出（默认 `data/output/`） | ✅ |
| AI 提供商 | OpenAI / Qwen / DeepSeek / Ollama 任一 | 视功能而定 |

> `python main.py` 会自动检测并创建虚拟环境、安装依赖，环境准备大部分可省略手动步骤。

## 3. 安装

```mermaid
flowchart TD
    A[git clone 仓库] --> B{已有 .venv?}
    B -- 否 --> C[python -m venv .venv]
    B -- 是 --> D[激活虚拟环境]
    C --> D
    D --> E[pip install -e .]
    E --> F[安装完成]
```

```bash
git clone https://github.com/neopen/video-clip-agent.git
cd video-clip-agent

# Windows
python -m venv .venv && .venv\Scripts\activate.bat
# Linux / macOS
python -m venv .venv && source .venv/bin/activate

# 安装依赖（editable 安装会同时注册 penclip-cli 入口；本项目无 requirements.txt）
pip install -e .
# 开发环境用：pip install -e ".[dev]"
```

## 4. 配置 AI 提供商

```mermaid
flowchart TD
    A[复制 .env.example 为 .env] --> B{选择提供商}
    B -->|OpenAI| C[填 OPENAI_API_KEY]
    B -->|Qwen| D[填 QWEN_API_KEY]
    B -->|DeepSeek| E[填 DEEPSEEK_API_KEY]
    B -->|Ollama 本地| F[填 OLLAMA_BASE_URL]
    C --> G[设 AI_PROVIDER]
    D --> G
    E --> G
    F --> G
    G --> H[启动时自动加载]
```

```bash
cp .env.example .env
```

编辑 `.env`，取消注释并填写所选提供商：

```ini
# 提供商: openai | qwen | deepseek | ollama
AI_PROVIDER=qwen

QWEN_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxxxxx
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_MODEL=qwen-plus
```

| 提供商 | 环境变量 |
| :-- | :-- |
| OpenAI | `OPENAI_API_KEY` / `OPENAI_BASE_URL` / `OPENAI_MODEL` |
| Qwen | `QWEN_API_KEY` / `QWEN_BASE_URL` / `QWEN_MODEL` |
| DeepSeek | `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL` / `DEEPSEEK_MODEL` |
| Ollama | `OLLAMA_BASE_URL`（默认 `http://localhost:11434`）/ `OLLAMA_MODEL` |

> 配置采用双通道：`config.json`（用户本地覆盖）+ `.env`（环境变量，优先级更高）。

## 5. 启动服务

```mermaid
sequenceDiagram
    participant U as 用户
    participant M as main.py
    participant E as AppBaseEnv(setup_env)
    participant V as uvicorn
    participant A as FastAPI app

    U->>M: python main.py
    M->>E: 环境检测（Python/venv）
    E->>E: venv 不存在则创建
    E->>E: 安装依赖
    M->>V: 启动 uvicorn（host/port/workers）
    V->>A: 加载 penclip.app:app
    A->>A: 启动钩子：编译图 + 注册 Agent
    A-->>U: http://localhost:8000
```

```bash
python main.py                          # 默认 0.0.0.0:8000
python main.py --port 8080              # 自定义端口
python main.py --host 0.0.0.0 --port 8000  # 生产（多进程需 Redis）
```

启动成功后：

- API 文档：http://localhost:8000/docs
- ReDoc：http://localhost:8000/redoc

> 热重载（reload）与多进程（workers>1）互斥，同时启用时强制 workers=1。

## 6. 验证

```mermaid
flowchart TD
    A[GET /health] -->|200 healthy| B[POST /api/v1/sessions]
    B --> C[POST /api/v1/tasks 提交指令]
    C --> D[GET /api/v1/tasks/task_id/result 轮询]
    D -->|needs_confirmation| E[POST /api/v1/tasks/sessions/id/confirm]
    E --> D
    D -->|success| F[读取 data 与 suggestions]
    D -->|failed| G[读取 message 修正指令]
```

```bash
# 1. 健康检查
curl http://localhost:8000/health

# 2. 建一个会话，后续指令与确认都挂在它上面
SESSION=$(curl -s -X POST http://localhost:8000/api/v1/sessions | jq -r .session_id)

# 3. 提交自然语言指令（任务异步执行，只返回 task_id）
TASK=$(curl -s -X POST http://localhost:8000/api/v1/tasks \
  -H "Content-Type: application/json" \
  -d "{\"user_input\": \"做个混剪：红色开头，绿色中间，蓝色结尾\", \"session_id\": \"$SESSION\"}" | jq -r .task_id)

# 4. 轮询结果：高风险指令会停在确认门
curl -s http://localhost:8000/api/v1/tasks/$TASK/result | jq -r .needs_confirmation

# 5. 确认放行（同样返回 task_id，回到第 4 步轮询这个新任务）
curl -s -X POST http://localhost:8000/api/v1/tasks/sessions/$SESSION/confirm | jq -r .task_id

# 6. 查看会话进度：phase / slots / matched_slots / undo_depth
curl -s http://localhost:8000/api/v1/sessions/$SESSION | jq
```

> 素材登记、分析、匹配、合成同理，把 `user_input` 换成对应指令即可；合成（`渲染`）也是高风险指令，必须经第 5 步确认才会真正出片。

## 7. 一次完整调用时序

```mermaid
sequenceDiagram
    participant C as 客户端
    participant API as FastAPI
    participant P as neotask.TaskPool
    participant H as CentralHub(中枢)
    participant R as CapabilityRegistry
    participant A as Agent
    participant S as StateManager

    C->>API: POST /api/v1/tasks {user_input, session_id}
    API->>P: submit(data) 生成 task_id
    API-->>C: 返回 task_id（异步）
    P->>H: worker 调 hub.process(user_input, session_id)
    H->>H: 意图识别（V0.1 关键词，长词优先）
    H->>H: 风险评估
    H->>R: find_by_intent(意图)
    R-->>H: 匹配的能力/Agent
    H->>H: 高风险 → 存入挂起队列，返回 needs_confirmation
    H->>A: 低风险 → execute(params, context)
    A->>S: 更新 AssemblyState
    A-->>H: ExecutionResult
    H-->>P: HubResponse → 任务结果
    C->>API: GET /api/v1/tasks/{task_id}/result 轮询
    C->>API: POST /api/v1/tasks/sessions/{session_id}/confirm
    API->>P: submit(action=confirm)
    P->>H: hub.confirm(session_id) 续跑挂起指令
    C->>API: GET /api/v1/sessions/{session_id} 查进度
```

## 9. 常见问题

| 问题 | 处理 |
| :-- | :-- |
| 端口被占用 | `python main.py --port 8080` 换端口 |
| FFmpeg 未找到 | 安装 FFmpeg 并加入 PATH，或配置内置 FFmpeg 路径 |
| 给了视频 URL 却分析失败 | V0.1 的素材登记只记录引用、不下载，请改用本机可读的视频文件路径 |
| 多进程下任务状态分裂 | 多进程模式需 Redis（配置 `REDIS_URL`），否则任务在进程间不可见 |
| 换了 provider 不生效 | 确认 `.env` 中 `AI_PROVIDER` 与对应 `*_API_KEY` 都已填写并取消注释 |
| 想直接看接口 | 访问 http://localhost:8000/docs |
